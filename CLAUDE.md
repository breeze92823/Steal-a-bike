## Current state: the lobby
The lobby is built (from the reference screenshots of the original game: north, south, west and east views): a lego plaza walled in by purple terraces, an east-west road, the bike plots south of the road, the shops north of it, and the SAFE ZONE lane north through 44 zones (1-4 hand-built from the user's screenshots: grass, raised grass, sand, snow + ice gate; 5-44 generated from 40 themes, each guarded by sleeping police that get stronger with distance), with procedural sound and per-zone lighting moods. The HUD is in place with live timers, ticking cash, the spawn announcement banner and Ride My Bike (rides your bicycle, faster, outside the safe zone only); the other buttons only toast "coming soon". There are no game rules yet: no stealing, buying, saves, audio or networking. The old boat-racing code is in git `HEAD` (`git show HEAD:src/<file>`); check there before rewriting something generic (windows shell, net, audio).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the lobby (`LAYOUT`, `LANE` (zones 1-4: north edge, floor height, guard post, sign amount; the ice gate), `MOODS` + `ZONE_THEMES` (the 40 generated zones), `GUARD_TIERS`, `ZONE_GEN`, `AUDIO`, `RIDE`, `PALETTE`, `TIMERS`, `ANNOUNCE`, `HUD_START`, `SLOW_MODE_SCALE`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> clouds, lighting, lobby (lobby/market/valley) + HUD, player body -> avatar (async) + name tag -> loop (physics, interpolate player, avatar animator, camera, clouds, `updateFx`, HUD, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z; 0 = south; `Math.PI / 2` = east).
- **Lobby** (+X east, -Z north, metres; layout numbers in `LAYOUT`): `lobby.js` ground slab, road + curbs, the seven plots (`plotCenters`/`plotOwners`: yours with treadmill, Upgrade Treadmill / Upgrade Plot signs and the Club Tourer bicycle; two neighbours with two-deck garages full of motorbikes and neon treadmills; unclaimed ones), `terraceWall` (purple or brown-cliff terraces with stepped orange/green tops, panels, ledges, windows, trees), the yellow bike logo on the south wall, ghosts and pumpkins. `market.js` the strip north of the road: lamp + planter, INVITE ONLY podium, star board, Halloween!/SELL! stalls with glow discs, Fuse Machine, Trails stall + glowing pool, FREE GIFT! chest, MOST CASH board, Exclusive bike bubble. `valley.js` the junction stub (chevrons, crossing, SAFE ZONE paint, red line). `lane.js` the zone list: builds each zone into its own group when you come within range (one per frame), shows only nearby zones, hides the hub far up the lane, and on entering a zone sets its lighting mood (`lighting.setZoneMood`), ambience (`audio.setBed`) and HUD title card. The zones: `zone1.js` grass (lily-pad puddle, guard asleep on a police motorbike by three bicycles, Halloween portal + live sign only while the event is open), `zone2.js` a raised grass plateau (0.7 m step; patrol car, mint scooters, "600 Recommended" sign, yellow/green flecks), `zone3.js` sand (yellow-topped cliffs, cacti, SWAT van post, "4K"), `zone4.js` the snow basin in ice cliffs (gate wall with waterfalls and the white arch, armoured truck post, "20K", snowflakes) ; `zones.js` builds zones 5-44 from `ZONE_THEMES` (floor step, themed cliffs, neon entrance gate with the zone name, set piece, decor, weather, motes, aurora/ghosts extras, guard posts with rarer bikes + tags + auras, "Recommended" signs; the last zone ends at a "More zones coming soon" wall). `decor.js` the prop library those themes name (trees, palms, bamboo, mushrooms, crystals, torches, lanterns, tombstones, cauldrons, gears, steam pipes, neon buildings/signs, jellyfish, kelp, coral, lava/water pools, pyramid, volcano, stage, castle gate, fountain, planets, ...). `police.js` the detailed guard fleet in strength order (police bike, sports bike, car, SUV, SWAT truck, armoured truck, tank, hover tank; marks 0-4 add chrome, light bars, gold trim, underglow) with shared slow-flashing red/blue lamps. `lanekit.js` the zones' shared pieces (floors with colliders, patches, pixel puddles, clumps, cacti, snowy pines, snow chunks, parked bikes in dashed bays, the "Recommended" sign); `vehicles.js` police car, SWAT van, armoured truck, police motorbike, scooter, sleeping officer, parking bay. `kit.js` the shared lego kit: stud textures/materials (`studMat`, UVs in metres via `meterBox`/`sbox`), canvas signs, `liveLabel`, `bikeTag`, and props (voxel trees, pumpkins, ghosts, lamps, "!" markers, `bicycle`, `motorbike`). `fx.js` per-frame effects (`onFrame`, `bob`, `sparkles`, `risingText`, `zzz`, `motes`, `weather`); effects registered while a zone builds (`setFxOwner`) sleep while that zone is hidden, and particle counts scale with the preset's `particles`. `audio.js` procedural WebAudio (no files): ambience beds per zone, snoring guards, waterfalls, thunder; starts on the first tap/key, M or the HUD speaker mutes. `timers.js` the shared event/race countdowns.
- **Draw calls**: each of lobby/market/valley ends with `bakeStatic(root)` (bake.js), which merges every mesh that never moves into one mesh per material. Anything that moves must be flagged `userData.dynamic = true` (`bob` does it) or it gets merged and freezes.
- **HUD**: `hud.js` + `hud.css` (Battle Pass, Shop, Index, Slow Mode, gems/cash, hotbar 1/2, Ride My Bike + gear (shown past the red line; the safe zone takes you off the bike), Daily Rewards, Starter Pack, x2 Speed + boost timer, event and race countdowns, the announcement banner). Sizes are in `--u` design pixels (1 at 1920x990). The left column stays out of Boxity's reserved corner, and on short landscape screens moves beside the chat. On touch, the hotbar/money/timers sit above the thumb controls. `nametag.js` is the headshot + name over your character.
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing/ride (seated, pedalling); tunables in `ANIM`). While `player.riding`, main.js shows your bicycle under the avatar with its wheels rolling.
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- `world.js`: the clouds (one baked mesh, slowly turning).
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` `bake(group)` merges a group's meshes to one mesh per material (keeps the group's transform); `bakeStatic(root)` does it in place for everything that doesn't move.
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn, 1/2 hotbar slots, M mute. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
